# Contributing

Thank you for helping. Everyone here follows the [code of conduct](https://github.com/home-mandate/.github/blob/main/CODE_OF_CONDUCT.md).
This page applies to every repository in the `home-mandate`
organization; a repository may add its own rules in its own `CONTRIBUTING.md` (the
specification does: [spec/CONTRIBUTING.md](https://github.com/home-mandate/spec/blob/main/CONTRIBUTING.md)).

## Issues and discussions

- A bug report is most useful with the input that shows it. For the specification, the
  best report is a conformance case that fails.
- A larger change starts with an issue, so that it can be discussed before you spend
  time on it.
- Questions and ideas belong in Discussions.
- Security problems never go into a public issue: use **Security → Report a
  vulnerability** in the affected repository.

## Pull requests

- One topic per pull request, with a description of what changes and why, and how it
  was tested.
- The checks of the repository must pass.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/)
  (`fix: …`, `feat: …`, `docs: …`).
- By contributing, you agree that your contribution is licensed under the license of the
  file you change.

## AI assistance

AI assistance is entirely fine, as long as the person using it can fully review and
understands the result. Whoever submits a change is responsible for every line of it. A
pull request does not need to say whether AI was involved.

## Who decides

The maintainer of the repository decides what is merged. How decisions across
repositories are made is in [GOVERNANCE.md](https://github.com/home-mandate/.github/blob/main/GOVERNANCE.md); what implementations keep is
in [IMPLEMENTATIONS.md](https://github.com/home-mandate/.github/blob/main/IMPLEMENTATIONS.md).
